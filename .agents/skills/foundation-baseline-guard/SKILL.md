# 管理端基础骨架保护

## 本项目边界

本仓库承担 vben 管理端基础工程。基础骨架包括 monorepo/workspace 工具链、应用启动、路由与访问守卫、认证会话、安全请求链、共享 packages、统一表格与表单适配、偏好设置、i18n 基础设施、构建和 CI。

业务页面、业务路由与菜单、API wrapper/type、业务状态、页面表单和表格、业务权限、业务 i18n、文档和测试属于业务扩展。页面功能应优先落在应用业务目录并复用现有组件和适配器。

## 编辑前判定

开始修改前记录当前提交、业务来源、允许范围和受影响应用，并把文件分为业务变更、业务接入变更、基础骨架核心变更。

本仓库自身是前端骨架来源时，共享 packages、工具链或应用壳演进仍属于核心变更；必须评估所有管理端应用和下游业务仓。

## 核心变更确认

核心代码默认只读。只有已复现的工程缺陷、安全/稳定性问题、现有组件或扩展点无法承载需求，或开发人员明确要求演进基础工程时，才可以提出修改。

实施前必须向开发人员说明并等待明确确认：

```text
问题与复现证据:
应用业务层不可解决的原因:
拟修改 workspace、package、应用壳、路由或安全链路:
对页面、权限、会话、构建产物和下游项目的影响:
替代方案及取舍:
typecheck、测试、构建、浏览器冒烟和回退方案:
```

一般性的页面开发或“保持一致”不构成核心代码修改授权。明确同步某个基础版本时，只授权已核对的来源差异。

## 实施与复核

- 禁止为单一页面修改共享 package、路由守卫、认证会话或请求安全底座。
- 禁止另建重复的表格、表单、权限、状态或 API 基础设施。
- 业务迁入时保留页面语义和契约，但按当前 router、access、API client、组件和 i18n 机制接入。
- 修改后逐项解释核心路径差异，并验证受影响应用的 typecheck、测试、构建和可见流程。
- 最终记录业务变更、接入变更、获批核心变更、受影响应用、实际验证命令和回退方式。
